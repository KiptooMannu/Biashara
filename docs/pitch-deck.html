The problem

MSMEs are the backbone of the economy
and are served by nothing that fits.

Fragmented tools

Separate systems for stock, till, books and customers. The data never meets, so nobody can answer a question that crosses two of them.

Reports, not answers

Existing software says sales were 28,000. It does not say why they fell, what it cost, or what to do — the owner is left to work that out.

Nothing "just right"

Spreadsheets are too thin. SAP and Oracle are unaffordable and need a consultant. The middle is empty.

The cost is invisible. A shop that runs out of cooking oil at 2pm does not see a loss — it sees a slightly quieter day. The revenue that never happened is the hardest number in business to notice, and no MSME tool surfaces it.

The shift

Every number arrives with a cause
and a recommended action.

Differentiator 1

An assistant that shows its working.

Ask it anything about the business. It classifies the intent, runs the analytics queries that answer it, and composes a reply from what came back — then hands you the figures it used and names the query behind them.

ASKED
"Why did profits fall?"
ANSWERED

Gross profit is actually up KES 107,447 against the previous 30 days — KES 883,466 versus KES 776,019. Operating expenses rose by KES 189,300 over the same period, so the improvement is partly offset by higher costs.

figures used:
 · Revenue, last 30 days: KES 2,864,641
 · Gross profit, last 30 days: KES 883,466
 · Gross profit, prior 30 days: KES 776,019
 · Lines currently out of stock: 0
source: sales.sumGrossProfitBetween + expenses.sumBetween

It contradicted the question

The premise was that profits fell. They had not. A model optimised for agreeableness would have explained a decline that never happened — and the owner would have acted on it.

Deliberately not a language model

An owner about to reorder stock or chase a debtor has to be able to check the claim. A rule-based assistant over real queries cannot invent a number. One method, compose(), is the swap point for Spring AI — the query layer becomes the model's tool surface.

Differentiator 2

Same application, radically different surface.

Permissions held, by role

Of a 63-permission catalogue
  • Permission-based, not role-based. Endpoints declare hasAuthority('inventory.product.create'). Roles are database rows bundling permissions, so a business can invent a role at runtime without a code change.
  • Hierarchy is one integer. You may only create or assign roles at a strictly higher level number than your own — which makes "managers can only create users in their own department" enforceable rather than aspirational.
  • The UI is convenience; the server is the boundary. A cashier's sidebar hides Finance, and typing the URL still returns 403.

Architecture

A modular monolith with the seams already drawn.

21 screens, permission-filtered navigation, ApexCharts

63 permissions as authorities, per-endpoint authorization
12 bounded contexts as packages
iam · inventory · sales · crm · procurement · finance · hr · asset · project · analytics · ai · notification
Spring Data JPA · Hibernate 6.6
37 repositories, aggregation pushed into the database
Neon serverless PostgreSQL 18
Shared-schema multi-tenancy with a tenant discriminator

Why a monolith, deliberately

Each package maps 1:1 onto a service boundary in the target microservice design. Extracting a service later means lifting a package, not untangling a codebase. The trade is explicit: one deployable to run and reason about now, with the boundaries drawn so the split stays cheap.

Multi-tenancy that cannot leak

Every tenant-owned row extends TenantAwareEntity. Every query is scoped by tenant, and the tenant comes from the caller's token — never from a request parameter. A request cannot ask for another business's data because it never gets to name the business.

Engineering

Four bugs that only show up if you actually run it.

01 Lombok silently never ran

JDK 23 stopped auto-discovering annotation processors on the classpath. Every generated getter was missing — and it only surfaced where one class called another's, so most of the codebase looked fine. Fixed by declaring the processor path explicitly.

02 IDENTITY ids killed batching

Hibernate must round-trip per insert to read a generated key back, which disables JDBC batching. Seeding was 12,000 individual round trips to a US-East database: over 40 minutes. Pooled sequences brought it to ~3 minutes.

03 Neon's pooler cached stale plans

The pooler multiplexes clients onto shared server connections and caches statement plans against them, so a schema change raised "cached plan must not change result type". Fixed with prepareThreshold=0.

04 The demo business was insolvent

Seeded expenses (995K) exceeded gross profit (229K) while the health score read "Excellent" — a dashboard contradicting itself. Rebalanced to 2.38M revenue → 735K profit → 502K expenses → +234K net.

Also caught: a like-for-like comparison bug — month-to-date revenue was being compared against a full previous month, showing a spurious 5.5% decline caused purely by the missing days. Now compared day-for-day.

Access control, per role

Probed as owner, general manager, cashier, finance and HR. The cashier is refused finance, HR, procurement, reports, audit and AI; HR is refused inventory, sales and finance; finance is refused HR and procurement. Privilege escalation and cross-department creation both return 403.

Transactional integrity

A POS sale was recorded end to end: stock moved 64 → 61 with a matching STOCK_OUT movement carrying the correct running balance and the invoice reference. Stock and the ledger cannot drift, because they are written in one transaction.

The seeder prints its own row counts on every boot and flags any table below the floor — so an empty screen is caught in a log line, not during a walkthrough.

Why this order

Channels first because an ERP that cannot email an invoice is not yet a product. Migrations second because after that the schema stops being disposable.

Why offline matters here

Kenyan retail runs on intermittent connectivity. A till that stops when the line drops is not deployable, whatever the feature list says.

Why the AI swap is last

The value is the grounded query layer, and it already exists. The model is an interface change, not the substance.
